# Family

A native iOS 26 app that keeps a household in sync: one shared view of everyone's day, who's handling which ride, where everyone is, shared lists, chores and allowance, meals, and a family board. Built with SwiftUI, SwiftData and Liquid Glass, with no third-party dependencies.

> **Status:** Phase 1 of 8 (project, design system, data model, sample household, tab shell). See [`docs/PLAN.md`](docs/PLAN.md) for the full plan and build order.

## Requirements

- Xcode 26 or later (CI builds with the newest Xcode 26.x on the `macos-26` runner)
- iOS 26.0 deployment target; Swift 6 language mode with complete concurrency checking
- A paid Apple Developer account to run on devices, use iCloud sync, and ship through TestFlight

## Run it in the Simulator

1. Open `Family.xcodeproj`.
2. Choose the **Family** scheme and an iPhone simulator.
3. Run. Debug builds load the sample household, **The Parkers**, automatically, so every screen has realistic data without iCloud.

Debug-only tools are at the bottom of **Settings** (tap the avatars at the top left of Today):

- **Use App As**: see the app as Sam, Alex, Emma or Liam
- **Load Sample Household**: reload The Parkers
- **Reset All Data**: delete everything on this device

The sample data's dates are relative to the day it was loaded, and it refreshes once a day so the demo always looks current. Launch arguments `-FamilyResetSampleData` (reload) and `-FamilyInitialTab calendar|map|home|search` (open a tab) help with UI testing.

## Configure signing (once)

Edit **one file**, `Config/Signing.xcconfig`:

```
DEVELOPMENT_TEAM = ABCDE12345      // your Team ID
BUNDLE_ID_PREFIX = com.yourname    // a reverse-DNS prefix you own
```

Everything else derives from those two values:

| Item | Identifier |
|---|---|
| App | `$(BUNDLE_ID_PREFIX).family` |
| Widgets extension | `$(BUNDLE_ID_PREFIX).family.widgets` |
| Share extension | `$(BUNDLE_ID_PREFIX).family.share` |
| App Group | `group.$(BUNDLE_ID_PREFIX).family` |
| iCloud container (Phase 4) | `iCloud.$(BUNDLE_ID_PREFIX).family` |

With automatic signing, Xcode registers the App IDs and the App Group the first time you build to a device. If Xcode reports a missing App Group, open each target's **Signing & Capabilities** tab once and let it fix the provisioning profile.

## Project layout

```
Family.xcodeproj         Generated by scripts/generate_project.py
Config/                  xcconfigs, entitlements, Info.plist additions
App/                     The app target (folder is synced: new files are picked up automatically)
  Root/                  TabView shell, toolbar menus, Next Up accessory
  Features/              Today, Calendar, Map, Home, Search, Settings
  Support/               Session state, lookups, actions, DEBUG tools
  Resources/             Asset catalog (app icon, accent color)
Widgets/                 WidgetKit extension
ShareExtension/          Share extension
Packages/FamilyKit/      Local Swift package shared by every target
  FamilyCore             Foundation-only logic: recurrence, summaries, domain types
  FamilyData             SwiftData models, store, occurrence expansion, sample household
  FamilyDesign           Design system: member colors, avatars, chips, rows, glass controls
design/icon/             App icon source (SVG generator and renderer)
scripts/                 Project generator, CI helpers, SDK probe
```

The Xcode project uses file-system-synchronized groups, so adding a Swift file to `App/`, `Widgets/` or `ShareExtension/` needs no project edits. Run `python3 scripts/generate_project.py` only when you add a target or change build settings.

## Architecture

- **SwiftUI first**, with `@Observable` state and dependency injection through the environment (`HouseholdSession` today; the service layer joins in later phases).
- **SwiftData is the local source of truth.** Models store relationships as UUID foreign keys, so CloudKit records can arrive in any order. Every synced model carries `ckSystemFields` (the CloudKit change tag) and `dirtyFields` (fields edited since the last upload), which drive per-field conflict resolution.
- **The store lives in the App Group container**, so widgets and the share extension read the same data.
- **Recurrence** is handled by `RecurrenceEngine` in FamilyCore: daily/weekly/monthly/yearly rules, specific weekdays, "2nd Tuesday" and "last Friday", count and until limits, and per-occurrence exceptions. It's DST-safe and unit tested.
- **Design system:** each member has a color from a curated set of system colors, used for row color bars, chips and map pins. Liquid Glass is reserved for floating controls (tab bar, toolbars, the map's member chips, the "I've got it" button); content rows stay solid.

## Tests

- `Packages/FamilyKit/Tests/FamilyCoreTests`: the recurrence engine and the day summary. These also run on Linux (`swift test` in `Packages/FamilyKit`).
- `Packages/FamilyKit/Tests/FamilyDataTests`: the sample household, occurrence expansion with exceptions, and list item check state.

Run them all in Xcode by opening `Packages/FamilyKit` and pressing ⌘U, or from the command line:

```
cd Packages/FamilyKit
xcodebuild test -scheme FamilyKit-Package -destination 'platform=iOS Simulator,name=iPhone 17 Pro'
```

## Continuous integration

`.github/workflows/ios.yml` runs on every push, on GitHub's `macos-26` runner:

1. Builds the app and its extensions (Debug), and **fails on any warning**.
2. Runs the FamilyKit tests on an iPhone simulator.
3. Builds the Release configuration, also with zero warnings.
4. Takes screenshots of every tab in light and dark mode and uploads them as the `screenshots` artifact.

`.github/workflows/sdk-probe.yml` prints real declarations from the installed iOS SDK for the regexes in `scripts/probe-patterns.txt`. It's used to check new iOS 26 API signatures instead of guessing.

## App icon

`App/Resources/Assets.xcassets/AppIcon.appiconset` has light, dark and tinted 1024 × 1024 variants, generated from `design/icon/make_icon.py` (vector shapes) and rendered by `design/icon/render_icon.js`.

To build the layered Liquid Glass version in **Icon Composer** (Xcode → Open Developer Tool → Icon Composer):

1. Export the three people as separate SVGs (edit `make_icon.py` to emit one `person(...)` per file, or copy each `<g>` group out of `AppIcon-light.svg`).
2. Create a new icon. Set the background to a white-to-#F4F7FB vertical gradient (light) and #1C2230-to-#0B0E15 (dark).
3. Add three layers, back to front: the purple person (left), the mint person (right), then the blue person (center). Put each in its own group so each gets its own glass specular highlight.
4. Set each layer's opacity to about 90% and turn on **Translucency** so the overlaps blend as in the flat artwork.
5. Save `AppIcon.icon` into `App/`, then in the app target set **App Icon** to `AppIcon` and delete the old `AppIcon.appiconset`.

## Screen Time (out of scope for v1)

Screen Time controls need the **Family Controls** entitlement (requested from Apple per app), a child iCloud account in a Family Sharing group, and the FamilyControls, ManagedSettings and DeviceActivity frameworks. Apple must approve the entitlement before the app can ship through TestFlight or the App Store. A `ScreenTimeService` protocol with a no-op implementation is added with the service layer, so this can be added later without touching the rest of the app.
